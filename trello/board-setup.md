Suggested lists: Backlog, Ready for Testing, In Progress, Blocked, Failed / Investigating, Ready for Retest, Done. Case cards link definitions, requirements, runs and evidence; use priority/feature labels. Move to Done only after required checks pass; preserve previous run history.

For a genuine defect, create a separate card with its real BUG ID and template fields. Link Requirement → Case → Run → Bug in both directions. Keep blocked questions visible; no fake cards for hypothetical examples. Mirror decisions in the repository so it works without tracker access.

Jira/Redmine equivalents: cards become issues; lists become states; fields hold severity, priority, environment and links. Available issue types/workflows depend on project configuration.
